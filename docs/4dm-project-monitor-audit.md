# 4DM Project Monitor — teknisk audit og gap matrix

Status: aktiv implementeringsaudit, opdateret 2026-09-02. Dette dokument beskriver observeret repository-tilstand. Filtilstedeværelse er ikke det samme som bestået brugeradfærd, og seed/preview er ikke live-evidens.

## Cyklus 014-addendum

FØR-batchens efterladte, ikke-modtagne Storage-objekter har nu en afgrænset kildeløsning: kun annullerede eller udløbne intents leases atomisk, og en hemmelighedsbeskyttet serverroute sletter præcis den registrerede path via Storage API med retry-sikker kvittering. Migrationen og scheduler er ikke anvendt live; pgTAP/DB-lint, serverekstraktor, canonical `drone_assets`, UI-pause/reload-resume og rigtig Auth/Storage/TUS er **AFVENTER**. De ældre gap-rækker nedenfor beskriver præ-slice-checkpointet.

## Konklusion

GoFreyra har allerede størstedelen af de tekniske byggeklodser til en 4DM Project Monitor, men de er spredt mellem projektworkspace, to kortflows, Connect, rapporter og flere parallelle data-/integrationsservices. Der skal derfor ikke bygges en ny app eller skiftes stack. Den rigtige vej er at gøre projektet til ejer af én sammenhængende rejse og konsolidere eksisterende funktioner omkring en fælles geometri-, tids-, proveniens- og evidensmodel.

Det første observerede kundestop var projektgrænsen: “Redigér” ændrede kun midlertidige tegninger, og fuldskærmseksporten kunne udelade `projects.geometry_polygon` eller erstatte en fejl med demoindhold. Cyklus 005 har lokalt samlet alle skriveveje om én fail-closed Polygon-kontrakt, gjort den gemte grænse redigerbar med Gem/Annuller og indsat den canonical grænse i eksporten. Pure/service-regressioner er grønne; save → reload i rigtig database, rolleadgang og interaktiv browseraccept er fortsat `AFVENTER`.

## Auditgrundlag

- Faktisk stack: TanStack Start/Router/Query, React 19, TypeScript, Vite, Leaflet/Geoman og Supabase/Postgres/Storage.
- Centrale ruter: `/app/projects`, `/app/projects/$slug`, `/app/projects/geometry/$slug`, `/app/projects/map/$slug` og `/app/connect/*`.
- Centrale dataveje: `projects.geometry_*`, `project_areas`, `project_media`, `uploads`, `drone_flights`, `drone_assets`, `field_observations`, `observations`, `actions`, `evidence_files`, `action_evidence`, `audit_events`, `reports`, `documents`, `data_sources` og `integration_runs`.
- Staging-schema, private buckets, anon PostgREST og et transaktionelt A/B-tenant-scope er verificeret. Rigtig Auth-/Storage API, alle roller og eksterne adaptere er fortsat `AFVENTER`.
- Login/signup og unauthenticated redirect er observeret i den interaktive lokale browser med ren konsol. En credentials-båret kunderejse er fortsat `AFVENTER`.

## Højeste prioriterede kundestop

1. **Projektgrænse round-trip:** klient-/servicekontrakten er lokalt rettet, herunder seed-after-clear og ugemte-edit guards; rigtig database-reload, atomisk boundary+RPC-snapshot, metrics-friskhed, browserrejse, versionskonflikt og rolleadgang er fortsat `AFVENTER`.
2. **Tenant- og Storage-sandhed:** staging-SQL/anon er verificeret; rigtig Auth-/Storage API, alle roller og `spatial_ref_sys` mangler; produktion er NO-GO.
3. **Fragmenteret navigation og dataejerskab:** samme projekt har flere kort- og uploadindgange uden fælles tids-/datasetmodel.
4. **Tavse preview-fallbacks:** flere integrationer kan vise demo-data efter live-fejl.
5. **Uploadløfter uden job/resume:** UI annoncerer typer og filstørrelser, som den faktiske pipeline ikke kan færdigbehandle sikkert.
6. **Ingen faglig reviewkæde:** observation → ændring → vurdering → handling → evidens → rapport er ikke samlet.

## Bindende implementeringsrækkefølge

1. Pålidelig Polygon-validering og edit/save/reload/export round-trip på den eksisterende `projects.geometry_polygon`.
2. Versioneret projektområde og datamodel, efter Supabase preflight/RLS-plan.
3. Projektbundet historisk tidslinje.
4. Før/Efter-parring og synkroniseret visning.
5. Canonical lagvælger og datakatalog.
6. Observationer, change events og faglig reviewkø.
7. Evidens/audit og observation→handling.
8. Versionsfast rapportgenerator.
9. Canonical drone-/feltflow.
10. Konsoliderede integrationer og avancerede analyser.

Hvert trin gennemføres som en afgrænset vertikal funktion. Live migration, Storage, RLS og eksterne smoketests udføres først med særskilt miljømandat; ukendt tilstand må ikke erstattes af påstået evidens.

## Auditdækning og begrænsninger

- Routes, layouts, navigation, komponenter, hooks/state/data fetching, services, tests, mock/seed-data, migrations, RLS-policyhistorik, Storage-kode, serverfunktioner, API-ruter og integrations-/jobtabeller er søgt og stikprøveinspiceret.
- Kortbibliotek, GeoJSON/WMS/WFS/STAC/COG-kode, CRS-antagelser, geometrieditering, beregninger, parallelle kortinstanser og håndtering af integrationfejl er kortlagt. Performance for store Polygoner er nu begrænset med en lokal admission-gate; reel stor-data-/rasterbelastning er ikke benchmarktestet.
- Feature flags og TODO/FIXME-markører er søgt. Fund er kun klassificeret som implementeret, når den aktive datavej og test kunne observeres; en skjult eller ubrugt fil tæller ikke som funktion.
- Edge Functions, kø-/jobmodeller og synkroniseringshistorik findes delvist, men deres deployede runtime kunne ikke verificeres.
- Git branches blev kontrolleret via remote refs. GitHub issues og pull requests var ikke tilgængelige i det lokale auditgrundlag og er derfor ikke brugt som evidens.
- Staging-SQL/anon og lokal browser-smoke er observeret; den credentials-bårne browserrejse, rigtig Storage API, produktion og eksterne kilder er fortsat `AFVENTER`. Dette checkpoint er ikke en produktionsgodkendelse.
